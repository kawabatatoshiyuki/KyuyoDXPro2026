# 帳票方式の比較検証（手順2：官製様式の寸法精度）

対象：源泉徴収票（`R_源泉徴収票.xlsx`、現行テンプレート 102KB / A4・方眼紙レイアウト）

実機で2方式を通し、いずれも **A4（210×297mm）** のPDFを生成できることを確認した。

| 観点 | A: xlsxテンプレ流用 | B: QuestPDF（コード描画） |
|---|---|---|
| 検証結果 | ClosedXMLで既存テンプレ読込・流し込み→**Excelで公式レイアウトのままPDF化**（427KB / 210×296.9mm） | mm固定セルでフォーム描画→PDF（63KB / 209.9×297mm） |
| 既存資産 | ◎ 既存約25種テンプレをそのまま使用、寸法は現行と完全一致 | × 全帳票を作り直し |
| 外部依存 | △ Excel COM はサーバ非推奨／要ライセンス。**LibreOffice headless が現実解** | ◎ 純.NET、外部プロセス不要 |
| サーバ常駐適性 | △ 変換プロセスの常駐管理が必要 | ◎ そのまま常駐可 |
| 寸法精度 | ◎ 官製様式が作り込み済み（年次様式もExcelで踏襲） | ○ mm指定で精度確保可。ただし全欄の作り込み工数が大 |
| 様式改正の追従 | ◎ Excelで様式修正→差替え（非技術者でも可） | △ コード修正・再ビルドが必要 |
| 速度・大量出力 | △ 変換プロセス起動コスト | ◎ 高速 |
| ライセンス | LibreOffice=MPL無償／Excelはサーバ不可 | QuestPDF=売上100万USD未満は無償 |

## 結論（推奨：ハイブリッド）

- **官製様式（源泉徴収票・法定調書・給与支払報告書・徴収簿 等）→ Approach A**
  - 寸法が厳格で年次に様式変更があるため、既存xlsxテンプレ資産を活かせる A が最適。
  - サーバでは Excel COM ではなく **LibreOffice headless**（`soffice --headless --convert-to pdf`）か、サーバ対応の商用xlsx→PDFライブラリを使う（Excel COM はMSがサーバ用途を非推奨）。
- **社内帳票（給与明細書・各種台帳 等、自由レイアウト・高頻度・大量）→ Approach B（QuestPDF）**
  - 外部依存なし・高速で常駐に向く。明細PoC（`PaySlipPdfGenerator`）で実証済み。

## Approach A 実機検証（法定調書合計表、2026-06-16）
- LibreOffice **26.2** を導入（winget `TheDocumentFoundation.LibreOffice`）。
- 現行テンプレ `R_合計表.xlsx` へ `LegalRecordSummaryXlsxGenerator` で集計値を流し込み → `LibreOfficePdfConverter`（`soffice.com --headless --convert-to pdf`）でPDF化。
- 結果：filledxlsx 91KB → PDF 218KB、**寸法 210.0×297.0mm＝A4ぴったり**（PDFのMediaBoxで確認）。
- 目視：soffice で PDF→PNG 化して確認、官製様式（FE0104）に提出者欄・6区分の集計値が正しく配置。**官製様式の寸法・レイアウトはテンプレ準拠で完全再現**。
- 変換コマンド例：`soffice.com --headless --norestore -env:UserInstallation=file:///<一時profile> --convert-to pdf --outdir <out> <in.xlsx>`
- 配置：オンプレ各サーバに LibreOffice を1つ導入し、`LibreOfficePdfConverter.FindDefault()` で soffice を解決。並行プロセス競合回避のため変換ごとに専用 UserInstallation プロファイルを使用。
- PoC：`tools/PayCalcDXPro.LegalRecordPoc`、自動テスト：`LibreOfficePdfConvertTests`（soffice/テンプレ存在時に有効化）。
- ライセンス：LibreOffice=MPL2（外部プロセス呼び出しのみ＝当社コードは非伝染）。オンプレ同梱は可能だが商標ポリシー留意。商用.NET変換ライブラリ（Aspose等）は外部プロセス不要の代替案。

## 顧客環境非依存方式の採用（方式①、2026-06-16）
顧客サーバに LibreOffice 等の別モジュールを入れたくない要件のため、**実行時は純.NET で完結する方式①**を採用。
- **構成**：xlsxマスター →(座標自動抽出 `XlsxOverlayLayoutExtractor`)＋(背景PDF：開発機LibreOfficeで1回生成・同梱) →(実行時 `LegalRecordSummaryPdfGenerator` が **PdfSharp(MIT)** で背景PDFへ値をオーバーレイ)。日本語は OS同梱フォント(.ttc)を `TrueTypeCollection` で単体TTF化して使用。
- **顧客環境依存ゼロ／追加ライセンス費ゼロ**。値の配置はxlsx編集に追従、罫線等の様式変更時のみ背景PDFを再生成（開発機）。
- 実機検証：官製様式FE0104に集計値が正位置・A4で出力（PoC `tools/PayCalcDXPro.LegalRecordPoc`）。
- 比較：方式②（商用xlsx→PDF：罫線含めテンプレ編集だけで完結だが有償）／方式③（QuestPDF全描画：無償だが全欄作り込み）。「VBReport的にテンプレ修正で罫線まで」を厳密に満たすのは②、コスト最小で“ほぼ”満たすのが①。

## 様式アセットの同梱と再生成（方式①の完全自己完結化）
法定調書合計表の様式は **DLLに埋め込み**（`src/PayCalcDXPro.Reporting/Assets/`）。実行時は外部ファイル・外部プロセス・顧客導入物に一切依存しない。高レベルAPIは `LegalRecordSummaryReport.CreatePdf(summary, 提出者)`。
- `R_合計表.xlsx`：座標抽出元のマスターテンプレ（`XlsxOverlayLayoutExtractor`）。
- `R_合計表_背景.pdf`：官製様式の罫線・固定ラベル（背景）。

### 様式改正時の再生成手順（開発機でのみ実施。出荷物にLibreOfficeは含めない）
1. `Assets/R_合計表.xlsx` を編集（罫線・ラベル・`**…` セルの移動）。
2. 背景PDFを作り直す：マーカーを消したxlsxをLibreOffice headlessでPDF化。
   - `LegalRecordSummaryXlsxGenerator.ClearMarkers(xlsx)` → 一時xlsx → `LibreOfficePdfConverter.ConvertToPdf` → `Assets/R_合計表_背景.pdf` に上書き。
   - PoC `tools/PayCalcDXPro.LegalRecordPoc` が同一処理を実行するので、その出力 `output/背景.pdf` を `Assets/` へコピーしてもよい。
3. リビルド。値の配置はxlsx編集に自動追従（座標は実行時に再抽出）、罫線は背景PDFに反映される。
