# リリース前セキュリティ診断チェックリスト（給与計算DXPro ブラウザ版）

本アプリは **ローカルPC・単一会社・単一管理者アカウント運用のスタンドアロンWebアプリ**（localhost 待受）である。
この前提のもと、リリース前に以下を確認する。各項目はチェック欄に日付と確認者を記入する。

---

## 1. SQLインジェクション対策
- [ ] 値は全て `SqliteCommand.Parameters.AddWithValue`（`$パラメータ`）でバインドしている。
- [ ] SQL文へ文字列連結しているのは **固定の識別子（テーブル名・列名）または `PRAGMA table_info` 由来のスキーマ名のみ**で、ユーザー入力を連結していない。
- [ ] ファイルパス等を SQL に埋める箇所は `'` を `''` にエスケープしている（例：`VACUUM INTO`）。
- 確認方法：`CommandText` を使う箇所を全て目視レビュー。`$"..."` 内にユーザー入力変数が入っていないこと。

## 2. XSS対策
- [ ] Blazor の自動 HTML エンコードに委ねている（`MarkupString` / `Html.Raw` / JS `innerHTML` を使っていない）。
- [ ] 自己完結HTML（ログイン画面・エラー案内等）で差し込む値は `WebUtility.HtmlEncode` 済、または固定文字列である。
- 確認方法：`grep -R "MarkupString|Html.Raw|innerHTML"` が空であること。

## 3. 認証・認可の分離
- [ ] 認証（Cookieログインゲート）と認可（ロール Claim / `AddAuthorization`）が分離実装されている。
- [ ] セキュリティアカウント設定時、データ系エンドポイント（PDF/CSV）が未認証アクセスを拒否する。
- [ ] マイナンバー全桁復号は `管理者` / `マイナンバー閲覧` ロールでのみ可能。
- 確認方法：未ログイン状態で各データURLへ直アクセスし `/login` へ誘導または 403 になること。

## 4. IDOR対策
- [ ] データは単一会社・単一データセットであり、URL の `Number` / `No` を変更しても自社の自データのみが対象であることを確認（越境の余地がない設計を維持）。
- [ ] 将来、複数会社・複数利用者対応を追加する場合は、所有者チェックを別途実装する。

## 5. パスワード管理
- [ ] パスワードは平文保存せず、PBKDF2-HMAC-SHA256（21万回以上・ランダムsalt）でハッシュ化している。
- [ ] 検証は `CryptographicOperations.FixedTimeEquals`（タイミング攻撃耐性）を使用している。

## 6. エラー情報の管理
- [ ] 画面（Snackbar・戻り値メッセージ）に例外メッセージ・スタックトレース・ファイルパス・SQL 等の内部情報を表示していない。
- [ ] 例外詳細は `AppErrors.Log` 経由でサーバーログにのみ記録している。
- [ ] 本番環境で `ASPNETCORE_ENVIRONMENT=Development` になっていない（詳細エラー画面の抑止）。
- 確認方法：`grep -R "ex.Message|e.Message"` が UI 表示経路に無いこと。

## 7. 依存ライブラリ管理
- [ ] `dotnet list package --vulnerable --include-transitive` を実行し、脆弱性が 0 件であることを確認。
- [ ] ビルド時の NuGetAudit 警告（`Directory.Build.props` で有効化）が出ていないことを確認。
- [ ] 使用中の .NET / 主要パッケージの EOL・サポート期限を確認（.NET 8 → .NET 10 LTS への移行計画を含む）。
- 確認方法：リリースごとに上記コマンドを実行し、結果を記録に残す。

## 8. セキュリティ診断（リリース前テスト）
- [ ] 本チェックリスト 1〜7 を全て確認済み。
- [ ] 未ログイン・一般権限での主要画面／URL のアクセス権限テストを実施。
- [ ] バックアップ取込・復元の異常系（不正ファイル・別PC鍵・改ざん）でアプリが安全に拒否することを確認。
- [ ] 確認結果（日付・確認者・バージョン）を記録として保存。
